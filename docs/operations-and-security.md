# 运维与安全

## 上游与密钥

只接受每个包配置声明的 GitHub 仓库和精确资产名称。GitHub API 返回的 SHA-256、大小、资产 URL、Release 标签和固定提交被记录并校验。stable 选择正式版；latest 按发布时间选最新非草稿版本。

上游 APK 的依赖、许可证、版本或架构与配置不符时中止，不自动忽略差异。软件包不会被重新编译、删减依赖或替换服务脚本。原始 SHA-256 与追加签名后的 SHA-256 均记录在 manifest。

生产私钥只放在 `repository-signing` Environment Secret `APK_SIGNING_KEY`，不提交、不上传 artifact、不写日志。签名步骤临时文件权限为 0600，步骤结束自动移除；公开站点仅含从私钥导出的公钥。

环境限制默认分支并要求审批。PR 工作流只运行配置与单元测试。签名后的包安装检查在另一个没有私钥的 job 运行。

## 保留策略

每个通道中的每个包只保留一个版本。latest 可选择正式版或预发布版；若上游没有预发布版，则使用最近发布的正式版。

站点从空目录生成，每次整体替换，旧 APK、旧源码和旧 manifest 不复制。Actions 中间 artifact 保留 1 天，仅用于本次 job 间传递，不作为历史软件源；GitHub 的日志与任务记录由平台策略管理。

发布失败时不触碰当前站点。发布成功后不提供旧版本下载或回滚 feed。设备若仍缓存旧索引，应先 `apk update` 再安装；不承诺旧索引引用的 APK 持续可用。

## 签名与完整性

上游包经过 SHA-256 和 APK 数据校验后追加仓库签名，保留原始内容。签名 job 会独立查询 GitHub Release，重新核对标签对应的提交、资产 ID 和 SHA-256，并直接计算待签 APK 的摘要；若上游在组装与签名之间变更，则停止本次发布。此步骤只读取元数据，不重新下载 APK。`packages.adb` 用同一密钥签名；全站文件被 `SHA256SUMS` 覆盖，清单另有 RSA/SHA-256 签名 `SHA256SUMS.sig`。

首次信任公钥前，与自己生成时保存的指纹或可信 Actions 签名任务摘要核对；从同一未知站点同时下载公钥和指纹不构成独立信任。后续不得随每次工作流重新生成私钥。

当前工具只支持单个生产公钥，尚未实现多密钥自动过渡。轮换前须通过现有可信渠道给设备分发新公钥，之后再更换 Secret 并重新发布，避免设备失去验证能力。

## 设备文件边界

Bootstrap 只管理本仓库专用配置和公钥，不覆盖官方 feeds 或用户自己的 `customfeeds.list`。如果专用文件被用户修改，APK 可能按配置文件保护策略保留它。面向订阅者的 LuCI 配置步骤见[项目 README](../README.md)。

通过 `包名@lauyv` 安装会把仓库标签持久写入 `/etc/apk/world`。移除订阅或更换 bootstrap 前，必须先备份 world 并仅清理此标签，保留应用包条目和版本约束，再卸载配置包、删除专用文件；否则后续 APK 操作会因缺失仓库标签而失败。切换通道后按安装步骤重新添加标签。站点的 `install.txt` 保留 bootstrap 命令行安装方式；README 介绍无标签的 LuCI 配置方式。

## 故障

| 问题 | 处理 |
|---|---|
| GitHub 限流或下载失败 | 重试工作流；不发布空源 |
| 上游资产不存在或无 digest | 停止，确认上游发布是否完整 |
| 元数据变化 | 审核上游打包变更后更新对应包配置 |
| kmod 依赖不满足 | 确认官方 feeds 与固件内核匹配，不使用强制忽略依赖 |
| 签名或安装检查失败 | 不进入部署任务 |
| Pages 无法部署 | 检查 Pages 是否设置为 GitHub Actions、环境分支限制及权限 |

审计资料见站点 `manifest.json`：工作流 URL、Release ID、标签、资产 ID、源码提交、输入/输出 SHA-256、工具链版本、公钥指纹和索引摘要。
